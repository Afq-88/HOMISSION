# الأمان وحماية بيانات العملاء — «طلبك معنا»

> **صراحةً:** لا يوجد نظام «آمن تمامًا». هذا المستند يصف الحماية المطبَّقة فعلًا، وما تغطيه وما لا تغطيه، وما يلزم من إجراءات بشرية. **لم يخضع النظام لاختبار اختراق مستقل**؛ يوصى بمراجعة من مختص أمن معلومات في الشركة (وقانونية بخصوص أنظمة حماية البيانات المطبقة في الكويت) قبل استقبال بيانات حقيقية.

## ١) ما البيانات التي نجمعها
اسم العميل، هاتفه، بريده (اختياري)، جهته، تفاصيل طلبه وملاحظاته، وملخصات تواصل الموظفين. **لا نجمع**: بطاقات بنكية، صور هويات/وثائق، الرقم المدني، مواقع GPS. لا يُستخدم تقديم الطلب كموافقة على رسائل تسويقية.

## ٢) الحماية المطبَّقة
| الخطر | الحماية | مختبَرة آليًا |
|---|---|---|
| سرقة كلمة مرور موظف | **مصادقة ثنائية TOTP إلزامية** (رمز يتغير كل ٣٠ ث، لا يُقبل مرتين) + رموز استرداد مجزّأة تُستهلك مرة | ✔ |
| جلسة مسروقة / جهاز متروك | جلسة مطلقة ١٢ ساعة لا تتجدد، كوكي `__Host-` + `HttpOnly` + `Secure` + `SameSite=Strict`، إنهاء الجلسات عند تغيير كلمة المرور/تعطيل المستخدم | ✔ |
| تسريب جماعي عبر جلسة مخترَقة | **إعادة تأكيد الهوية (كلمة مرور + رمز) لمدة ٥ دقائق** قبل: تصدير بيانات التواصل، تنزيل نسخة، حذف، إخفاء هوية، إنشاء/تعديل مستخدمين، تغيير الإعدادات | ✔ |
| تخمين كلمات المرور | scrypt لتخزين كلمات المرور، حد محاولات لكل (IP+مستخدم) وللمستخدم وحده وللـIP، قفل مؤقت، رسالة خطأ موحدة وزمن ثابت | ✔ |
| الوصول لبيانات غير مخوّل | صلاحيات في الخادم: الزائر لا يقرأ شيئًا؛ الموظف يرى طلباته (وغير المسند لإدارته)؛ التصدير والحذف والإعدادات للمدير فقط | ✔ |
| حقن (SQL/XSS/CSV) | استعلامات مُعلمة، ترميز كل مخرجات الواجهة، سياسة CSP صارمة (`script-src 'self'`)، منع حقن الصيغ في ملفات Excel | ✔ + اختبار متصفح |
| CSRF | ترويسة مخصصة + فحص Origin + SameSite=Strict | ✔ |
| تسرب النسخ الاحتياطية | **تشفير AES-256-GCM** (مفتاح من عبارة عبر scrypt) قبل التخزين والتنزيل؛ كشف أي تعديل؛ صلاحيات 0600 | ✔ |
| سرقة قاعدة البيانات لأسرار 2FA | أسرار TOTP مشفّرة داخل القاعدة بمفتاح التطبيق (`APP_SECRET`) المنفصل عن القاعدة | ✔ |
| إنكار/تلاعب بالسجلات | **سجل عمليات متسلسل بالتجزئة** يكشف أي تعديل أو حذف؛ زر تحقق + `npm run verify-audit` | ✔ |
| الاحتفاظ بالبيانات أكثر من اللازم | أرشفة/**إخفاء هوية**/حذف بمدد قابلة للضبط، تمسح الأسماء والهواتف والنصوص الحرة وتبقي الإحصاءات | ✔ |
| اختراق الخادم | تشغيل بمستخدم بلا صلاحيات، شيفرة للقراءة فقط، عزل systemd، لا منافذ سوى 80/443/22، تحديثات أمان تلقائية، fail2ban، SSH بمفاتيح فقط، لا اعتماديات npm (سطح هجوم أصغر) | سكربت (لم يُنفَّذ على خادم حقيقي بعد) |
| اعتراض الاتصال | HTTPS تلقائي عبر Caddy، HSTS | عند النشر |
| الأجهزة اللوحية | لا تخزّن بيانات، مسح تلقائي، تحكم عن بعد بالإيقاف/المسح، رموز لا تحمل بيانات | ✔ |

## ٣) ما لا تغطيه هذه الحماية (يجب أن تعرفه)
- **قاعدة البيانات الحية غير مشفّرة على مستوى التطبيق.** من يخترق الخادم نفسه (صلاحية root) يصل للبيانات والأسرار. الحماية هنا بتقليل الاختراق (الطبقات أعلاه) وبتشفير القرص الافتراضي لدى Oracle لنسخ/لقطات القرص خارج الجهاز. (تشفير LUKS اختياري يتطلب إدخال عبارة يدويًا بعد كل إعادة تشغيل فيعطّل الاستمرارية — لم أفعّله.)
- **أمان الحساب السحابي نفسه:** من يملك حساب Oracle يملك الجهاز. فعّل المصادقة الثنائية على حساب Oracle وعلى GitHub، وقلّل من لهم صلاحية.
- **موقع البيانات:** تُخزَّن في منطقة Oracle التي تختارها (قد لا تكون داخل الكويت). تحقق من سياسة الشركة/الجهات التنظيمية.
- **العامل البشري:** لقطات الشاشة، مشاركة كلمات المرور، آيباد بلا قفل، تنزيل نسخ وتركها على أجهزة مفتوحة.
- **الاستمرارية:** خادم واحد؛ لا تكرار جغرافي. النسخ اليومية خارج الخادم ضرورية.
- لا حماية من هجمات حجب الخدمة الكبيرة (فقط حدود معدل وحدود حجم).

## ٤) قواعد تشغيل إلزامية للموظفين
1. كلمة مرور فريدة طويلة + تطبيق المصادقة على الجوال؛ لا تشاركها ولا تكتبها.
2. قفل الآيباد برمز + قفل تلقائي ≤ ٢ دقيقة؛ لا تترك لوحة الموظفين مفتوحة بلا مراقبة (الجلسة تنتهي بعد ١٢ ساعة).
3. لا لقطات شاشة ولا نسخ لبيانات العملاء إلى واتساب شخصي أو بريد شخصي.
4. التواصل مع العميل عبر القنوات الرسمية فقط، ولا تعد بما لم يُعتمد.
5. أي اشتباه (جوال ضائع، رسالة غريبة، طلب غير مفهوم) → أبلغ المدير فورًا.

## ٥) إجراءات المدير
- **يوميًا:** نزّل نسخة احتياطية (مشفّرة) واحفظها خارج الخادم، وافتح «سجل العمليات ← التحقق من السلامة».
- **أسبوعيًا:** راجع المستخدمين المفعّلين، عطّل من انتهت حاجته، راجع سجل الدخول الفاشل (`login_failed`).
- **عند ضياع جوال موظف:** «المستخدمون ← إعادة تعيين 2FA»؛ وللمدير نفسه: `sudo talabak-admin reset-2fa --username=admin`.
- **عند خروج موظف:** عطّله فورًا (تنتهي جلساته).
- **حفظ الأسرار:** `APP_SECRET` و`BACKUP_PASSPHRASE` في مدير كلمات مرور الشركة (لا في البريد). ضياع العبارة = نسخ لا تُفتح.

## ٦) دورة حياة البيانات المقترحة (عدّلها حسب سياسة الشركة)
| متى | ماذا |
|---|---|
| ١٩ نوفمبر ٢٠٢٦ – ٣٠ يناير ٢٠٢٧ | استقبال ومتابعة |
| بعد ٣٠ يناير | أوقف الاستقبال، التقرير الختامي، نسخة احتياطية نهائية مشفّرة محفوظة خارج الخادم |

| بعدها | حذف المؤرشف نهائيًا حسب المدة، وإتلاف النسخ الاحتياطية القديمة بحسب السياسة |

## ٧) خطة الاستجابة لحادثة (اشتباه تسريب)
1. **أوقف الاستقبال** («الإعدادات») وعطّل المستخدم/الجهاز المشتبه به.
2. أبدل كلمات المرور وأعد تعيين 2FA للجميع؛ دوّر `APP_SECRET` (يلغي أسرار 2FA).
3. شغّل «التحقق من سلامة السجل» وراجع الأحداث (`login`, `export`, `backup_download`, `delete`).
4. احفظ نسخة من الخادم والسجلات كدليل، ثم أعد النشر من نسخة نظيفة.
5. أبلغ الجهات الداخلية والتنظيمية والعملاء المتأثرين وفق ما يوجبه القانون (استشر الشؤون القانونية).

- [ ] منفذ SSH (22) مقيّد بعنوانك في Oracle Security List.
- [ ] جُرِّبت الاستعادة من نسخة مشفّرة على نسخة اختبار.

- [ ] مراجعة أمنية/قانونية من الشركة.

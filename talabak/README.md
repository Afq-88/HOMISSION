# طلبك معنا — دليل التشغيل

نظام عربي لاستقبال ومتابعة طلبات زوار معرض الصناعات لدى شركة النقل العام الكويتية (KPTC)،
من ١٩ نوفمبر ٢٠٢٦ إلى ٣٠ يناير ٢٠٢٧، وقابل لإعادة الاستخدام في فعاليات أخرى (من «الإعدادات»).

> **حالة الجاهزية:** التطبيق يعمل ومختبَر محليًا (راجع «ما اختُبر»). **لم يُنشر بعد على رابط عام**، لذلك لا يُعد جاهزًا لاستقبال بيانات عملاء حقيقيين إلا بعد النشر على **HTTPS** مع قرص دائم، واختبار الرابط والرمز على جوال حقيقي. لا يوجد QR نهائي قبل ذلك.

## ١) التشغيل
المتطلبات: Node.js ‏22.5 أو أحدث. لا توجد مكتبات خارجية (قاعدة SQLite مدمجة في Node).

```bash
cd talabak
npm start                      # http://localhost:3000
npm run create-admin -- --username=admin --name="اسم المدير"   # يطبع كلمة مرور مؤقتة مرة واحدة
```
- الزائر: `/` ‏— الجناح (جهاز لوحي): `/kiosk` ‏— الموظفون والمدير: `/staff`.
- بدون مدير لا يمكن دخول لوحة الموظفين؛ لا توجد كلمات مرور ثابتة في الشيفرة.

### متغيرات البيئة
| المتغير | الغرض |
|---|---|
| `DATA_DIR` | مكان القاعدة والنسخ (يجب أن يكون **قرصًا دائمًا**) |
| `TRUST_PROXY=1` | عند وجود وسيط HTTPS (Render/Railway/Nginx/Cloudflare) |
| `COOKIE_SECURE=1` | عند التشغيل المباشر على HTTPS |
| `BACKUP_EVERY_HOURS` / `BACKUP_KEEP` | النسخ التلقائي (الافتراضي كل ٦ ساعات، ٤٠ نسخة) |

### التنبيهات والمراقبة (اختياري، بمتغيرات بيئة)
`NTFY_TOPIC` (تنبيه جوال بكل طلب جديد بلا بيانات شخصية) و`HEARTBEAT_URL` (نبض حياة كل ٥ دقائق إلى healthchecks.io أو مثيله). سكربت التثبيت يهيئهما ويضيف مراقبًا ذاتيًا يعيد تشغيل التطبيق إن تجمّد.

### تصميم صفحة الزائر («محطة الجناح»)
مشهد أفق الكويت (أبراج الكويت) يتبدل بحسب الوقت (نهار/غروب/ليل بتوقيت الكويت)، وحافلة KPTC تعبر الطريق، وكل خدمة «خط» بلونه ورسمه المتحرك، وتذكرة استلام تُطبع مع ماسات احتفالية. الخطوط (Reem Kufi وIBM Plex Sans Arabic، ترخيص OFL) والرسوم مستضافة محليًا: لا اتصال بأي طرف خارجي، وتعمل دون إنترنت على الجهاز اللوحي. يُحترم تفضيل «تقليل الحركة». للمعاينة: أضف `?tod=day` أو `?tod=dusk` أو `?tod=night` للرابط. ملفات التصميم: `public/visitor.css`, `public/art.js`.

### الأمان وحماية البيانات: اقرأ `SECURITY-AR.md` أولًا
مصادقة ثنائية إلزامية، إعادة تأكيد الهوية للإجراءات الحساسة، نسخ احتياطية مشفّرة، سجل عمليات مقاوم للتلاعب، إخفاء هوية بعد المعرض، وتشديد للخادم. **لم يخضع لاختبار اختراق مستقل.**

### النشر المجاني ١٠٠٪ (الموصى به): انظر `deploy/FREE-HOSTING-AR.md`
خادم Oracle Always Free بسكربت واحد (`deploy/vm-setup.sh`) مع HTTPS تلقائي، أو حاسوب الشركة مع Tailscale Funnel بلا بطاقة. الخطط المجانية في Render وأخواتها لا تصلح (بلا قرص دائم أو تنام).
نزّل نسخة احتياطية يوميًا من «النسخ الاحتياطي ← تنزيل».

### النشر على Render (مدفوع — اختياري؛ الملف `render.yaml` في جذر المستودع)
1. ادخل Render ← **New ← Blueprint** (أو افتح `https://dashboard.render.com/blueprint/new?repo=https://github.com/Afq-88/HOMISSION`) واربط حساب GitHub بالمستودع.
2. اختر الفرع `claude/kptc-request-app-3t4trj` (أو `main` بعد الدمج وعدّل `branch` في الملف). سيُنشئ Render خدمة `talabak-maana` بقرص دائم ١GB على `/data` في منطقة Frankfurt.
3. سيطلب منك Render قيمة `BOOTSTRAP_ADMIN_PASSWORD`: اكتب كلمة مرور مؤقتة قوية (١٠ أحرف+، حروف وأرقام). تُنشئ أول تشغيل مديرًا باسم `admin` ويُجبَر على تغييرها عند أول دخول.
4. بعد اكتمال النشر يظهر الرابط (غالبًا `https://talabak-maana.onrender.com`). افتح `/staff` وسجّل الدخول.
5. **بعد أول دخول:** احذف المتغيرين `BOOTSTRAP_ADMIN_*` من Render ← Environment. ثم «الإعدادات ← رابط النشر العام» (ضع رابط Render)، ثم «الروابط» و«ملصق QR» واختبر كل رمز بجوال حقيقي قبل الطباعة.
> **التكلفة والشروط:** القرص الدائم يتطلب نوع خدمة مدفوعًا (Starter فأعلى) — راجع أسعار Render الحالية. الخدمات المجانية بلا قرص وتنام عند الخمول، فتضيع الطلبات ويتعطل التنبيه المباشر والأجهزة اللوحية؛ لا تستخدمها. القرص يمنع النشر بلا انقطاع، فتحدث إعادة تشغيل قصيرة عند كل نشر؛ لذلك `autoDeploy` معطّل، وانشر خارج ساعات المعرض.
> **النسخ الاحتياطي:** نسخ التطبيق التلقائية على القرص نفسه؛ نزّلها دوريًا من «النسخ الاحتياطي» أو عبر Render Shell، ولا تعتمد على القرص وحده.

### النشر العام (أي استضافة أخرى)
أي استضافة تشغّل Node أو Docker مع **قرص دائم** و**HTTPS**: خادم افتراضي (VPS)، أو Render/Railway/Fly.io مع Volume.
الملف `Dockerfile` جاهز (يتوقع مجلد `/data` مركّبًا). مثال: `docker run -p 3000:3000 -v talabak-data:/data talabak`.
> لا تستخدم استضافة بلا قرص دائم (مثل طبقات مجانية تمسح الملفات عند إعادة التشغيل) — ستفقد الطلبات.

## ٢) إنشاء الحسابات بصورة آمنة
1. المدير الأول: `npm run create-admin` (كلمة مرور مولَّدة تُعرض مرة واحدة، أو `--prompt` لإدخالها بنفسك). يُطلب تغييرها عند أول دخول.
2. من «المستخدمون» يضيف المدير الموظفين: تُولَّد كلمة مرور مؤقتة تُعرض مرة واحدة، ويجب تغييرها عند أول دخول.
3. التعطيل وإعادة التعيين من الصفحة نفسها؛ لا يمكن تعطيل آخر مدير. كلمات المرور مخزّنة بـ scrypt، والجلسات في كوكي HttpOnly/SameSite.

## ٢-ب) الإصدار الثاني: العمل عن بعد، الإدارات، QR الجناح
**استقبال لحظي على الآيباد.** افتح `/staff` في Safari ← زر المشاركة ← «إضافة إلى الشاشة الرئيسية» فيعمل كتطبيق بملء الشاشة. سجّل الدخول وفعّل 🔔 في الرأس (تنبيه صوتي + إشعار نظام). أي طلب جديد يظهر خلال ثوانٍ: نغمة، رسالة، عدّاد في عنوان الصفحة `(٣)`، وتمييز الصف. مؤشر «مباشر» يتحول إلى «غير متصل» عند انقطاع الاتصال.
> حدّ صريح: التنبيهات تعمل **والصفحة مفتوحة** (حتى لو في الخلفية قليلًا)؛ iOS لا يسمح بتنبيه تطبيق مغلق بلا «Web Push». أبقِ التطبيق مفتوحًا والشاشة مضاءة أثناء الدوام، أو اطلب مني إضافة Web Push/قناة رسائل رسمية لاحقًا.
**التحكم عن بعد بأجهزة الجناح:** «أجهزة الجناح» تعرض كل لوحي يفتح `/kiosk` (متصل/غير متصل، حالته، عدد طلباته) وتتيح: مسح الشاشة، تحديث الصفحة، إيقاف مؤقت برسالة، لافتة أعلى الشاشة، إعادة التسمية — لجهاز أو للكل. الأوامر لا تحمل بيانات عملاء.
**الإدارات:** كل خدمة مرتبطة بإدارة تُصنَّف إليها طلباتها تلقائيًا، ويغيّرها الموظف لكل طلب. الأسماء الافتراضية (خدمة العملاء، التشغيل، التسويق والعلاقات العامة، الأوناش، الورش) **مقترحة — عدّلها من «الإدارات»**. موظف مرتبط بإدارة يرى غير المسند لإدارته فقط. التقارير: تصفية بالإدارة + «تقرير عمل مخصص» (تجميع حسب إدارة/خدمة/حالة/مصدر/مسؤول/يوم/وسم/نتيجة مع مؤشرات المتابعة) وتصدير CSV.
**QR الجناح:** «ملصق QR» يولّد ملصق A4 جاهزًا للطباعة برابط يحمل وسم الجناح (`?s=qr_booth&b=booth1`)؛ الزائر يمسح فيسجّل أي طلب أو استفسار من جواله، فيصلك فورًا. الوسم يظهر في التقارير. **لا تطبع قبل نشر الرابط على HTTPS واختباره.**
**للعمل خارج مبنى الشركة:** «المندوبون» يمنح كل موظف رابط وQR شخصيًا؛ الطلب الوارد منه يُسند له تلقائيًا بمصدر «رابط مندوب ميداني». زر 📞 اتصال مباشر/نسخ الرقم/بريد في صفحة الطلب (يعمل من الجوال والآيباد).

## ٣) قبل المعرض (قائمة تحقق)
1. نشر الرابط على HTTPS، ثم «الإعدادات ← رابط النشر العام».
2. أدخل في «الإعدادات» فقط ما يُعتمد رسميًا: قناة المتابعة الرسمية، رقم الطوارئ الرسمي (يظهر مع الأوناش)، عبارة مدة الاستجابة. **ما يُترك فارغًا لا يُعرض للعميل.**
3. راجع «الخدمات والحقول» (خيارات مدد الاشتراك مقترحة وقابلة للتعديل — لا أسعار ولا عروض).
4. «الروابط وQR»: اختبر كل رمز بكاميرا جوال وسجّل طلبًا تجريبيًا (وسمه «تجريبي» ثم احذفه بعد الأرشفة)، ثم اطبع.
5. اللوحي: افتح `/kiosk` على المتصفح وفعّل «الوصول الموجَّه» (iPad: Guided Access) أو وضع Kiosk لمنع الخروج من الصفحة. مهلة الخمول والتحذير من «الإعدادات».
6. شعار الشركة: ضع الملف الرسمي في `public/brand/logo.png` فيظهر تلقائيًا (لم يُخترع شعار).
7. النموذج الورقي الاحتياطي: `/paper-form.html` (يُطبع من المتصفح).

## ٤) التشغيل اليومي
- **الموظف:** «الطلبات» ← مؤشرات سريعة (مسندة لي، غير مسندة، متابعات اليوم/المتأخرة، تحتاج استكمالًا، لم يبدأ التواصل) ← افتح الطلب ← وثّق التواصل ← غيّر الحالة/المسؤول/الخطوة/موعد المتابعة. «تسجيل طلب» لتسجيله نيابة عن الزائر.
- يرى الموظف الطلبات المسندة إليه وغير المسندة فقط. أول تحديث على طلب غير مسند يسنده إليه.
- «مكتمل/مغلق» يتطلب تسجيل النتيجة (وتوضيحًا لبعضها). «الإحالة» تتطلب ذكر الجهة، وتاريخها يُسجَّل تلقائيًا ولا تعني إتمام الخدمة.
- **رسالة المتابعة:** يجهّز النظام النص فقط (نسخ). زر «فتح واتساب» مخفي حتى يفعّله المدير بعد اعتماد القناة، ولا يرسل شيئًا تلقائيًا.
- **المكررات:** تُنبَّه فقط (نفس الهاتف+الخدمة+التاريخ)، والمدير يقرر التصنيف؛ لا دمج تلقائي.
- **التقارير (المدير):** يومي/أسبوعي/ختامي/مخصص، طباعة موجزة، تصدير CSV بترميز يفتحه Excel بالعربية. التصدير الافتراضي **بلا بيانات تواصل**؛ التصدير مع بيانات التواصل يتطلب تأكيدًا ويُسجَّل.

## ٥) النسخ الاحتياطي والاستعادة
- تلقائي كل ٦ ساعات إلى `DATA_DIR/backups`، ويدويًا من «النسخ الاحتياطي» أو `npm run backup`. النسخة متسقة وآمنة أثناء التشغيل.
- **انسخ مجلد النسخ دوريًا إلى مكان خارج الخادم** (نسخ على القرص نفسه لا يحمي من فقد القرص).
- الاستعادة: أوقف الخادم ← `npm run restore -- data/backups/<الملف>` (يفحص سلامة النسخة، ويحفظ الحالة الحالية أولًا) ← شغّل الخادم. جُرّبت فعليًا.

## ٦) إقفال الفعالية
1. «الإعدادات ← استقبال الطلبات مفتوح» ← أوقفه (تظهر رسالة الإيقاف للزوار).
2. التقرير الختامي (طباعة) + تصدير الملخص والطلبات.
3. نسخة احتياطية يدوية، وحفظها خارج الخادم.
4. حسب سياسة الشركة: «الاحتفاظ والأرشفة والحذف» (معاينة ثم تأكيد؛ لا شيء تلقائي).
5. فعالية جديدة: غيّر «رمز الفعالية» (مثل EX27) فيبدأ الترقيم من جديد وتبقى بيانات السابقة قابلة للتصفية.

## ٧) الخصوصية والأمان (ما نُفِّذ)
- الصلاحيات تُطبَّق في الخادم: الزائر لا يملك أي واجهة قراءة؛ الموظف يرى طلباته فقط ولا يصدّر ولا يحذف؛ المدير فقط للتصدير والحذف والإعدادات.
- لا يستعاد الطلب من الواجهة العامة بعد الإرسال (لا بوابة استعلام)، وبطاقة الاستلام تُخفي أغلب أرقام الهاتف.
- حماية CSRF (ترويسة مخصصة + SameSite + فحص Origin)، رؤوس أمان وCSP، تحديد معدل لتسجيل الدخول والإرسال، منع حقن الصيغ في CSV، سجل عمليات لكل إنشاء/تعديل/تصدير/حذف.
- بيان الخصوصية القصير ظاهر في النموذج والتذييل، ولا يُعد تقديم الطلب موافقة على رسائل تسويقية.
- التشفير أثناء النقل مسؤولية النشر (HTTPS)؛ التطبيق لا يشفّر القرص. استخدم تشفير القرص عند المزوّد إن لزم.

## ٨) ما اختُبر (آليًا)
`npm test` — ٢٠ اختبارًا على خادم وقاعدة حقيقيين: طلب لكل خدمة، الأرقام العربية والهاتف حسب الدولة، الحقول الناقصة و«غير محدد حاليًا»، الإرسال المتكرر بنفس المفتاح (٨ متزامنة → طلب واحد)، ٤٠ طلبًا متزامنًا بأرقام فريدة، حجب الزائر، قفل الدخول، صلاحيات الموظف/المدير، المكرر، مطابقة التقارير والتصدير للسجل، حماية CSV، إنشاء المستخدمين وتغيير كلمة المرور، إقفال الفعالية، النسخ الاحتياطي، الإدارات والتقارير الجدولية، البث المباشر، أوامر التحكم عن بعد بالأجهزة، وروابط المندوبين.
واختُبر يدويًا بمتصفح حقيقي: رحلة الزائر على آيباد وجوال، فشل الاتصال (لا رقم استلام)، تنزيل بطاقة الاستلام PNG، وضع الجهاز اللوحي (تحذير ثم مسح كامل بلا بقايا)، لوحة الموظف والمدير، الاستعادة من نسخة احتياطية عبر `npm run restore`.

اختُبر أيضًا بمتصفح حقيقي بثلاث جلسات متزامنة (مدير، جهاز لوحي، زائر جوال): وصول التنبيه للمدير خلال أقل من ثانية، وتنفيذ الإيقاف والاستئناف واللافتة والمسح عن بعد، وترحيل قاعدة بيانات قديمة.

**غير مُختبَر بعد:** تنبيهات الصوت/الإشعارات على آيباد حقيقي؛ زمن التعبئة (٢–٣ دقائق) بزوار حقيقيين — يلزم اختبار ميداني بعدة أشخاص؛ التشغيل على الرابط المنشور؛ ماسح QR على جوال حقيقي؛ الطباعة على طابعة الجناح.
